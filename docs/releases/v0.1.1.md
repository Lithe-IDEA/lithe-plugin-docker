## 中文

Docker for Lithe 0.1.1 可从容器详情打开 Lithe 原生终端，直接进入运行中的容器。

### 重点更新

容器 Shell 现在使用 Lithe 自己的终端，并跟随插件当前选择的 Docker 引擎。

#### ✨ 新功能

- 点击「打开终端」进入容器，可选择 `/bin/sh`、`/bin/bash` 或 `/bin/ash`。
- 再次点击显示已有会话，关闭后重开可保留最多 16 KiB 显示历史。
- 可显式关闭并释放终端与历史，删除容器或 Compose 分组前也会释放对应会话。

#### ⚡ 改进

- Shell 选择与终端按钮位于详情标签栏右侧，窄面板下自动换行。
- 终端提示支持中英文，停止或暂停的容器会明确提示先启动或恢复。

### 升级说明

- 在 macOS 版 Lithe 的「设置 → 插件 → 从磁盘安装」中导入本版本 ZIP，替换 0.1.0 或本地试用包。
- 终端功能需要支持 API-24 原生终端的 Lithe、本机工作区，以及终端 PATH 中可用的 Docker CLI；容器内需有所选 Shell。
- 新增 `terminal.create` 权限；核对来源、校验值及宿主权限提示后安装，创建与重开仍由宿主请求执行确认。

### 兼容性与已知问题

- 当前仅支持本机 macOS 和 Unix socket，不包含 Windows、远程工作区或 SSH/TLS/TCP 引擎支持。
- 重开会启动新 Shell，只恢复显示历史，不重放输入，也不恢复旧进程、Shell 变量或未提交的命令。
- 此包未附带 Lithe 发布者签名；后端的 ad hoc 签名不代表发布者认证，安装包在运行时保持只读。
- 真实 Core + Docker 路由、容器操作与包文件不变性检查已通过；完整原生终端交互仍待目标 Lithe 宿主验收。

如果 macOS 提示无法打开宿主 Lithe.app，请在「应用程序」中按住 Control 点按应用并选择「打开」；如果仍被阻止，可在终端执行 `xattr -dr com.apple.quarantine /Applications/Lithe.app`。仅对可信来源的应用使用。

Docker for Lithe 0.1.1 opens Lithe's native terminal from container details to enter a running container.

### Highlights

Container shells now use Lithe's own terminal and the Docker engine currently selected in the plugin.

#### ✨ New features

- Choose Open terminal to enter a container using `/bin/sh`, `/bin/bash` or `/bin/ash`.
- Reuse an existing session, or reopen a closed session with up to 16 KiB of display history.
- Explicitly close and forget terminals and history; removing a container or Compose group also releases its sessions first.

#### ⚡ Improvements

- Shell selection and terminal actions sit beside the detail tabs and wrap in narrow panels.
- Terminal messages support English and Chinese; stopped or paused containers prompt you to start or resume them first.

### Upgrade instructions

- Import this release's ZIP through Settings → Plugins → Install from Disk in macOS Lithe, replacing 0.1.0 or a local trial package.
- Terminals require Lithe with API-24 native terminal support, a local workspace, Docker CLI on the terminal PATH, and the selected shell inside the container.
- Installation requests the new `terminal.create` permission. Check the source, checksum and host permission prompt; creation and reopening still require host execution consent.

### Compatibility and known issues

- Local macOS and Unix sockets only; Windows, remote workspaces and SSH/TLS/TCP engines are not included.
- Reopening starts a new shell and restores display history only, without replaying input or restoring processes, shell variables or unsubmitted commands.
- This package has no Lithe publisher signature. The backend's ad hoc signature is not publisher authentication; the installed package stays read-only at runtime.
- Real Core + Docker routing, container operations and package immutability checks passed; complete native terminal interaction still needs target-host acceptance.

If macOS says it cannot open the Lithe.app host, Control-click it in Applications and choose Open. If it is still blocked, run `xattr -dr com.apple.quarantine /Applications/Lithe.app` in Terminal. Use this only for an app from a source you trust.
