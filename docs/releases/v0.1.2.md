### 重点更新

后端改用官方 Rust SDK 的结构化日志，诊断写入 Lithe 日志窗口中本次会话的 `plugins/io.github.lithe-idea.docker/host` 通道，级别、脱敏、轮转和保留由宿主统一决定。

#### ⚡ 改进

- 每个后端函数由 SDK 记录唯一的成功或失败终态，带函数 ID、耗时和稳定分类；列表、日志、统计、事件轮询、文件浏览和分块上传等高频请求的成功不再记 INFO。
- Docker 引擎不可达时只记一次 WARN，并区分 context 不存在、宿主不支持、权限不足、连接中断和无法连接；恢复后记一次 recovered。
- 自动拉取缺失镜像后创建容器成功、Compose 下线时网络仍被占用，各记一次 WARN。
- 后端启动失败不再向 stderr 打印。
- 官方 Rust SDK 改为仓库内的 vendor 副本，CI 与打包按逐文件 SHA-256 校验。

### 升级说明

- 需要提供 `litheLogging` 1 的 Lithe preview 开发版。稳定版 Lithe 0.6.7 没有该能力，能安装但后端无法启动，请继续使用 Lithe Store 中的 0.1.1。
- 预发布版本会被 Lithe Store 自动追踪跳过，暂不收录 Store。下载本版本 ZIP，在「设置 → 插件」的 ⚙ 菜单中选择「从磁盘安装插件…」导入，替换 0.1.1。
- 权限声明与 0.1.1 相同。

### 兼容性与已知问题

- 当前仅支持本机 macOS 和 Unix socket，不包含 Windows、远程工作区或 SSH/TLS/TCP 引擎支持。
- 此包未附带 Lithe 发布者签名；后端的 ad hoc 签名不代表发布者认证，安装包在运行时保持只读。
- Release 工作流用 Lithe preview `4dd3165` 的 Core 和真实 Docker 引擎运行端到端检查，并断言每次调用恰好产生一条日志终态；完整界面交互仍待目标 Lithe 宿主验收。

## English

Docker for Lithe 0.1.2 adopts Lithe's structured plugin diagnostics (`litheLogging` 1). This is a pre-release: it needs a Lithe preview build that offers `litheLogging` 1. Stable Lithe 0.6.7 cannot start this version's backend; keep using 0.1.1 there.

- [Project homepage](https://github.com/Lithe-IDEA/lithe-plugin-docker)
- [macOS package (universal Apple silicon / Intel)](https://github.com/Lithe-IDEA/lithe-plugin-docker/releases/download/v0.1.2/docker-0.1.2-darwin.zip)

- [All downloads](https://github.com/Lithe-IDEA/lithe-plugin-docker/releases/tag/v0.1.2)

### Highlights

The backend now uses the official Rust SDK's structured logging. Diagnostics go to the current session's `plugins/io.github.lithe-idea.docker/host` channel in Lithe's log window; the host decides levels, redaction, rotation and retention.

#### ⚡ Improvements

- The SDK records exactly one success or failure for each backend function, with its function ID, duration and a stable category. Successful high-frequency requests (lists, logs, stats, event polling, file browsing and chunked uploads) no longer log INFO.
- An unreachable Docker engine logs one WARN, distinguishing a missing context, an unsupported host, denied permission, a lost connection and an unreachable engine; recovery logs one `recovered` entry.
- Creating a container after automatically pulling its missing image, and a Compose down that leaves a network in use, each log one WARN.
- Backend startup failures no longer print to stderr.
- The official Rust SDK is vendored in the repository; CI and packaging verify every file's SHA-256.

### Upgrade instructions

- Requires a Lithe preview build offering `litheLogging` 1. Stable Lithe 0.6.7 lacks it: the plugin installs but its backend cannot start, so keep 0.1.1 from Lithe Store there.
- Lithe Store's tracker skips pre-releases, so this version is not listed in the Store. Download this release's ZIP and import it with Install Plugin from Disk… in the ⚙ menu of Settings → Plugins, replacing 0.1.1.
- Permissions are unchanged from 0.1.1.

### Compatibility and known issues

- Local macOS and Unix sockets only; Windows, remote workspaces and SSH/TLS/TCP engines are not included.
- This package has no Lithe publisher signature. The backend's ad hoc signature is not publisher authentication; the installed package stays read-only at runtime.
- The release workflow runs end-to-end checks against Core from Lithe preview `4dd3165` and a real Docker engine, asserting exactly one terminal log entry per call; complete UI interaction still needs target-host acceptance.
